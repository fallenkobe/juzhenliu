# 场景验证报告

日期：2026-10-27。范围：依据 [README](../README.md) 与 [TODO](../TODO.md)，验证 [架构方案](ARCHITECTURE.md) 的关键规则和异常处理。

阶段说明：此报告记录首轮架构模型验证；随后实现的 SQLite 业务集成和浏览器验证见 [Alpha 0.01 开发说明](ALPHA_0.01.md)。下文“未执行”是首轮分析时的状态，不代表后续代码尚未开发。

## 1. 结论

可以进入原型与基础工程开发。账号、分析、发布和投流之间的职责、数据及状态边界已明确，采用模块化单体与独立任务进程。**真实多账号服务和 DOU+ 商业闭环尚未具备放行证据。**

本轮完成了公开资料核对、设计走查和 40 个可执行模型场景。40 个模型场景全部通过，包含并发配额、幂等、撤销授权、超时、部分成功、预算、回调及数据口径。没有绑定真实账号、发布视频、创建 DOU+ 订单或花费广告费用。

## 3. 可复现方法

在项目根目录运行：

```powershell
python -m unittest discover -s validation -p 'test_*.py' -v
```

依赖：Python 3.10 或以上，全部使用标准库。本轮使用本机 Python 3.14 执行，退出码 0，结果 `Ran 40 tests`、`OK`。

- [参考模型](../validation/scenario_model.py)：最小状态、命令、预算和指标模型，没有网络代码或真实账号参数。
- [场景断言](../validation/test_scenarios.py)：以业务不变量驱动，包含失败路径和 20 个并发竞争者。
- 金额测试中 100 表示 **100 分的模型额度**，不是 DOU+ 最低金额或生产配置。
- 并发测试只检验模型锁保护下的结果，不是性能压测或数据库并发实验。
- “可信事件”是模型输入假设，不包含真实 HMAC 验签；“故障恢复”通过构造未决状态验证规则，不是实际杀进程、断电或恢复数据库。

## 6. 本轮识别并落实的架构修正

1. **绑定和读取分开。** 账号列表接口不能承担绑定、续登和解绑；已纳入供应商能力门控和外部操作引导。
2. **素材 URL 和执行端本地文件分开。** 对需要本地文件的接入方增加素材下发与节点边界，避免“API 能提交但节点没有文件”。
3. **真实能力与演示能力分开。** 默认 unknown，mock 不能打开真实发布或投流操作。
4. **发布结果与作品可见性分开。** 提交、审核、发表和公开独立判断，只有符合资格的作品才进入投流确认。
5. **业务意图与 HTTP 幂等键同时约束。** 防止用户或恢复程序换新键绕过未知结果的去重；不承诺跨系统 exactly-once。
6. **预算按确认日与跨日在途双重控制。** 明确“每日确认额度”不是平台每日实际消耗；停止申请和未知付款不释放预算。
7. **实际超支如实记录。** 预算是本系统发起操作的边界，不伪造外部账目以维持本地上限。
8. **分析数据遵守口径。** 无数据不是 0，付费归因不默认等于作品流量的一部分，也不直接构造自然流量。

## 7. 进入下一阶段的条件

当前允许开展基础工程和明确标记的原型。优先次序：

1. 按 [接入门槛 G1–G8](PROVIDER_CAPABILITIES.md) 获取供应商证据，优先个人准入、会员产品许可、绑定和 DOU+。
2. 建立数据库结构、持久任务和适配器契约，把 S01–S40 的业务断言迁移到真实服务测试，补齐 V01–V16。
3. 打通账号 → 数据 → 发布的少量真实闭环，验证实际可见性和标识映射。
4. 明确真实投流预算后再验证 DOU+，取得付款、审核、停止及对账证据。

任一核心能力缺失时，应在产品上明确禁用或展示真实人工步骤，不能以模拟测试覆盖率代替上线证据。
