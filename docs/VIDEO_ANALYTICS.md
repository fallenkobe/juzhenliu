# 视频分析：运行与部署

这是 `/videos` 的独立网页业务：通过 `/login` 登录矩阵流后，输入完整抖音视频链接或数字 ID，查询累计播放/赞/评/分享/收藏、历史逐日趋势、保存的查询结果和 CSV。所有 TikHub 请求由 Next 服务端发出，不需要本机助手、Edge、抖音 Cookie、OAuth 应用或 worker。

新增 `/accounts` 账号管理与视频分析共用管理登录：添加账号→填写抖音号→获取资料→核对预览→确认添加。数字抖音号优先调用Short ID接口，失败时最多尝试一次抖音号接口；字母抖音号使用抖音号接口，再通过sec_uid获取完整资料。返回抖音号必须与输入一致，UID/sec_uid也须一致；按真实UID去重，不把单纯数字猜成内部UID。此路径存在接口覆盖限制，未支持的抖音号明确报错，不自动选取相似账号。

密码仅用于登录矩阵流，账号管理和视频分析没有独立的密码框。未登录或会话失效时回到 `/login`，登录后返回原工作台/账号页/视频深链接；仅允许预设的站内返回路径。退出使共用会话失效。当前仍为一个实例所有者，尚未实现多用户注册或会员账号。

只保存白名单公开资料（昵称、头像、简介、UID/sec_uid、抖音号及粉丝/关注/作品/获赞等计数），不保存原始136字段。添加记录不是抖音OAuth授权或所有权认证，不能用于启用发布/投流。预览只属于发起查询的管理会话，有效10分钟；确认添加读取服务端预览，拒绝客户端伪造资料，不再次请求TikHub。列表和移除只读写本系统记录。

已添加账号的“查看作品”读取服务端保存的UID/sec_uid，按页调用App V3主页作品接口（每页20条、normal通道）。页面展示封面、标题、类型、发布时间和固定域名的作品URL；不向前端返回供应商原始分享追踪参数或媒体下载地址。逐条核对作者UID，图文单独标识并仅提供打开作品，未标记为已支持视频分析。

作品通过“加载更多”手动分页，按作品ID去重，显示接口返回的已加载数量和获取时间，不保证含私密、删除作品或账号所有历史。normal通道也可能延迟或遗漏最新作品。列表缓存30分钟，刷新至少间隔60秒；刷新第一页成功后清理后续旧页缓存，失败保留旧结果。每个新页面查询计入一次共享每日额度，移除账号会级联删除其作品缓存。没有定时刷新、自动全量翻页或批量分析。

视频“查看分析”在用户点击时发起一次受保护的查询，随后跳转 `/videos?videoId=...` 读取已保存报告。刷新或直接打开该地址只预填ID并读取已有报告，不自动调用付费接口；没有已保存结果时由用户点击查询。

## 数据边界

- 累计详情：`GET /api/v1/douyin/xingtu_v2/get_item_play_count`。累计播放采用服务商声明的含投流口径；不把它标为自然播放或官方核验值。
- 历史趋势：`POST /api/v1/douyin/xingtu_v2/get_item_report_trend`。请求只有视频 ID，日期、天数按响应展示。指定视频样本曾返回发布起连续30天，不能保证任意视频都有30天，也不能称为最近30天或自选日期范围。
- 返回的缺失值保留为空，负值原样保留；计数用整数字符串传输，避免大整数精度损失。日期断档或播放值缺失时不计算区间合计。
- 不展示定义不明的比率。CSV 单独保留 `valid_vv` 原字段，其精确定义未验收；不会与 `vv` 混用。
- 两块数据独立处理，部分失败时显示成功部分及错误。两块全部失败不覆盖以前保存的结果，不自动重试付费请求。

## 本机开发

在根 `.env` 配置（不要提交真实值，不使用 `NEXT_PUBLIC_`）：

```dotenv
TIKHUB_API_KEY=替换为自己的TikHub密钥
MATRIX_OWNER_PASSWORD=替换为至少24位的随机管理密码
MATRIX_VIDEO_DAILY_LIMIT=100
```

运行 `npm run dev:web`，打开 `http://127.0.0.1:3000/videos`。默认开发进程仅允许本机同源写请求；生产域名配置留给实际部署环境。若同一 `.env` 已有 `MATRIX_PUBLIC_ORIGIN`，本机开发时应暂时移除该配置或使用独立环境。

仅在 `NODE_ENV=development` 且未配置 `MATRIX_PUBLIC_ORIGIN` 的本机开发模式，管理密码允许至少3位。生产模式或已配置公网来源时仍要求至少24位；更换密码后重启Web，原管理会话会失效。

## 生产部署

本轮交付的是**可部署的单所有者 Web 功能**，不是已部署公网站点，也不是开放注册、会员计费和多租户 SaaS。部署者管理一个密码和一个 TikHub 账户。与 `/douyin` 复用管理会话，但不要求配置任何 `DOUYIN_*`。更换管理密码会使原会话失效；报告属于此单所有者实例，换密码不删除报告。

建议使用 Node.js 22.21.0、单个常驻 Node 实例与持久磁盘。数据库自动执行 `003_video_analytics` 迁移。默认 SQLite 位于 `MATRIX_DATA_DIR/alpha.sqlite`；不能使用随实例销毁的临时目录。PostgreSQL 兼容分支保留，但尚未真实验收。不适合直接作为静态站点或无持久磁盘的函数部署。

1. 在服务器放置代码，执行 `npm ci`、`npm run typecheck`、`npm test`、`npm run build`。服务器没有 Edge 时，助手浏览器夹具测试应在有浏览器的 CI/开发机运行，不在生产机安装或启动助手。
2. 在进程管理器环境或权限受限的根 `.env` 配置上面三项，另设 `MATRIX_PUBLIC_ORIGIN=https://你的域名`（不带末尾 `/`），并用绝对路径设置 `MATRIX_DATA_DIR`。保留 `ALPHA_MODE=demo`。
3. 执行 `npm run serve:videos`。只启动 Web，监听 `127.0.0.1:3000`（`PORT` 可改），不启动 worker 或助手。缺少密钥、强密码、合法 HTTPS 地址或合法额度配置时拒绝启动。
4. 用 Nginx/Caddy 等反向代理提供 HTTPS。若使用下面 Nginx 示例，先替换域名、证书路径和端口，由已有证书管理流程配置证书及续期。不要直接把 Node 回环端口暴露公网。
5. 用实际 HTTPS 域名验收：正确/错误密码、查询与导出、退出、刷新后已保存结果、上游断网/余额不足、每日额度。当前本机验收不等于实际域名、证书、反代和长期运行验收。

Nginx 示例只开放账号管理和视频分析，根路径转入视频分析；原演示 API、本机助手和 OAuth 不经此域名开放。`serve:videos` 设置独立模式，页面仅提供这两个Web业务入口。

```nginx
# http 块中，按实际业务容量调整登录入口限制。
limit_req_zone $binary_remote_addr zone=video_login:10m rate=5r/m;

server {
    listen 443 ssl;
    server_name videos.example.com;
    ssl_certificate /etc/ssl/videos/fullchain.pem;
    ssl_certificate_key /etc/ssl/videos/privkey.pem;
    client_max_body_size 8k;

    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_read_timeout 90s;

    location = / { return 302 /videos; }
    location = /videos { proxy_pass http://127.0.0.1:3000; }
    location = /accounts { proxy_pass http://127.0.0.1:3000; }
    location = /login { proxy_pass http://127.0.0.1:3000; }
    location = /api/videos/session {
        limit_req zone=video_login burst=5 nodelay;
        proxy_pass http://127.0.0.1:3000;
    }
    location ^~ /api/videos/ { proxy_pass http://127.0.0.1:3000; }
    location ^~ /_next/ { proxy_pass http://127.0.0.1:3000; }
    location / { return 404; }
}
```

`MATRIX_PUBLIC_ORIGIN` 必须与浏览器实际 HTTPS 地址完全一致，反代保留真实 Host，不改写 Origin。新业务校验同源、自定义请求头和管理会话；生产 Cookie 为 Secure/HttpOnly/SameSite=Lax，12小时到期。未登录不能读取记录、查询或导出。API 使用 `private, no-store`，CDN/代理不能另加公共缓存。不要在访问日志中记录请求体、Cookie、Authorization 或环境变量。

## 调用与费用控制

- 一次新查询最多发出2个固定 TikHub 请求；当前研究时标价合计约0.005美元，实际以供应商结算为准。没有后台轮询、定时刷新或自动重试。
- 完整成功结果缓存30分钟；点“更新数据”也至少间隔60秒。最近查询、已保存结果和 CSV 读取不请求 TikHub。
- 数据库中的60秒租约拦截同一视频并发查询；每日额度在发出请求前原子占用。失败也消耗一次内部查询额度，保守限制支出，不声称供应商一定对失败计费。
- 默认每日100次新查询（Asia/Shanghai），配置范围1–1000。额度是实例所有者共享，不是会员配额。不要把此参数当成供应商余额或绝对美元预算。
- 账号资料获取与视频查询共享该额度。一次新账号查询通常2次、最多3次固定端点调用；10分钟内同会话的有效预览可复用，确认添加和读取列表不调用供应商。同账号并发查询由90秒数据库租约拦截；身份不匹配时拒绝保存。
- 作品列表每页一次固定端点调用，与账号资料和视频分析共享额度。分页缓存30分钟、刷新最小间隔60秒；仅显式点击视频“查看分析”查询指标，页面跳转与刷新读取保存报告。不会自动遍历账号作品或批量分析。
- 页面保留最近30条入口；完整已保存报告在数据库中。定期备份数据库和环境配置，单独管理密钥，不提交到Git。轮换TikHub密钥后需重启进程。

## 检查范围

新增自动化覆盖输入/SSRF边界、身份、缺失与负数、大整数、日期断档、部分失败、缓存、并发租约、持久额度、生产来源配置和Cookie。历史生产构建浏览器测试覆盖登录、实际区间、表格、导出入口、部分失败、退出及390px布局；移动专项开发及验收已按用户要求暂停。本轮账号/作品Web验收覆盖添加、手动分页、类型区分、分析跳转与刷新不重查。浏览器数据使用合成响应，不冒充付费平台验收。真实视频联调与各轮检查范围见 `PROJECT_MEMORY.md`。

TikHub商业使用许可仍以供应商合同为准；此前条款核对记录见 [专项报告](TIKHUB_DATA_AUDIT.md)。本轮工程实现没有取得第三方再分发或付费会员服务的书面许可。


## 列表与分析导航

账号列表可按昵称、抖音号或UID搜索，按添加时间、粉丝量或昵称排序；不额外查询供应商。作品可按标题/ID和类型筛选、发布时间排序，范围仅限已加载页，加载更多仍需明确点击。

从作品进入分析后，可用“返回账号作品”回到 /accounts?accountUid=...。此路径与刷新页面只用 GET /api/videos/accounts/<uid>/works 读取保存的分页链（需要矩阵流登录），缓存过期不触发付费查询。无缓存时明确点击获取；刷新作品、加载更多仍按原费用规则处理。缺少供应商配置时保存列表仍可读取；筛选条件不跨页面保存。

最近查询入口提供最近30条已存报告的标题/ID搜索及部分数据筛选；不检索数据库中更早记录。选择报告会更新 /videos?videoId=... 深链接，刷新只读报告。历史趋势可切换播放/点赞/评论/分享/收藏，读取同一份返回数据；缺失与日期断档不连线、负值保留。顶部播放合计不随指标切换改变，CSV仍导出完整返回历史。


## 头像与封面

账号和作品优先显示接口返回的原始图片，保留高清头像及备用图片地址。图片通过受矩阵流登录保护的本站接口加载；失败显示提示和重试，不再隐藏成黑块。图片转发及重试不调用付费数据接口。服务端短期内存缓存30分钟，单进程最多32MiB；重启会清空缓存。

如果旧账号无头像或保存链接已过期，点击账号卡片“更新资料”；作品使用“刷新作品”。资料更新通过保存的账号标识查询一次固定资料端点，使用共享每日额度、至少间隔60秒，失败保留原资料。更新与图片重试的费用不同，界面已注明；无法取得图片时明确显示缺失或失败，不能保证所有过期/受限源都能加载。

图片接口只按账号/预览/作品ID查保存地址，限制HTTPS图片CDN、重定向、类型、文件头、大小和超时，不支持传任意URL；浏览器不发送第三方账号Cookie或TikHub密钥。既有 /api/videos/ 反代规则已覆盖这些路由。2026-10-27已在本机隔离生产服务验证用户指定的一个真实账号：头像和第一页4张封面（3视频、1图文）均通过本站图片接口返回HTTP200并由浏览器实际解码，已查看截图。此结果针对该账号和当时有效地址，不代表全部账号、长期过期恢复或公网网络验收。
