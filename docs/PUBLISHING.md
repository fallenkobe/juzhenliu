# 个人多账号发布模块（未上线、真实抖音待验收）

## 已实现范围

入口 `/publishing`，沿用矩阵流所有者密码和会话。`/accounts` 的公开资料分析保持独立，不把 UID/备注当作发布授权。第一版只为一个所有者管理自己的账号；无注册、会员、租户管理。

- 发布账号备注、预期抖音号，独立扫码流程、人工身份核对、登录检查、断开。
- MP4 上传（单文件 100 MB、个人累计 1 GB）、统一标题/描述/话题、显式 AI 声明。
- 勾选多个已确认账号，一次创建持久批次和每账号子任务；请求幂等。立即发布，不含预约、差异文案、自定义封面（采用平台默认）。
- 所有账号暂全局串行，单机 SQLite 租约防多个执行器重叠领取；浏览器独立 context。
- 自动填写后，网页展示实际页面截图；每个账号必须再次确认才允许点击发布一次。**这不是无人值守的一键全自动发布。**
- 提交后只记录“已提交”，不代表审核通过；未取得可核实作品 ID。失联/过期或提交后结果不清晰记 `unknown`，阻塞该账号后续任务；用户人工核实后解除，不自动重试原任务。

## 配置与运行（需要管理员另行批准安装引擎后操作）

现有 Web 服务之外，运行 `npm run publisher`（等效 `node --import tsx apps/publisher/index.ts`）。两进程必须使用相同仓库、`MATRIX_DATA_DIR`、所有者配置、加密密钥。不可跨主机共用 SQLite。第一版主动禁用 `DATABASE_URL` 模式发布执行，未验收 PostgreSQL/分布式共享素材。

```dotenv
MATRIX_PUBLISHING_ENABLED=0
# 真实执行须显式改为1；仅填写密钥不会启动任务
# MATRIX_PUBLISHING_KEY=<独立生成并安全保管的32字节随机数，64位hex>
# MATRIX_PUBLISHING_PYTHON=/absolute/path/to/venv/bin/python
# MATRIX_SAU_ROOT=/absolute/path/to/reviewed/social-auto-upload
```

生产仍须已有 `MATRIX_OWNER_PASSWORD` 强密码、`MATRIX_PUBLIC_ORIGIN` 精确 HTTPS Origin；部署需私密访问、HTTPS、受控文件权限和备份。不得把密钥写入前端、Git或日志。更换/遗失发布密钥后旧登录态无法恢复，应断开并重新登录。重启不会丢队列；过期任务不会重放。

引擎来源：[dreammis/social-auto-upload](https://github.com/dreammis/social-auto-upload)，固定提交 `3847fff01f5434a8a32829833163cd6723cabc59`。桥接器启动前校验 HEAD 和 tracked working tree；管理员仍须核查完整依赖/许可证及未跟踪代码，固定 Python 依赖并隔离运行。**本次没有安装或运行该上游项目，也没有生成依赖锁定环境。**

`python -I scripts/publishing/sau_bridge.py` 由执行器启动，不作为公开 HTTP 服务。桥接器复用该提交 `DouYinVideo` 的文案填写、可选声明方法及登录完成检查；不调用上游整套 `upload()`，不继承其发布重复点击、默认声明或浏览器反检测参数。API/队列/凭证保护在矩阵流侧实现。

## 登录态与安全边界

用户勾选同意扫码并在本服务器加密保存后才能创建登录任务。扫码图片通过当前所有者会话读取，不返回 Cookie。登录成功后仍须人工核对截图实际账号，10 分钟未确认丢弃待保存登录态。这里**没有平台 OAuth/UID 自动所有权认证**。

登录态 AES-256-GCM 加密存储，AAD 绑定所有者/账号；待确认登录态和短期短信控制也独立加密。运行时凭证仅通过私有 stdin 到子进程，浏览器 storage_state 在内存中，不写 plaintext Cookie 文件。子进程只继承最小环境，不传 TikHub、所有者密码或加密密钥。截图可能包含个人资料，任务完成清除；服务器内存/数据库仍是受信任边界，不是抵抗服务器管理员的安全隔离。

确认发布控制须绑定任务、60 秒有效、一次消费。执行器只有在有效租约和持久 owner 确认存在时才 ACK 提交；终态/旧租约事件不能回写。取消会停止子进程；一旦进入提交阶段不提供“安全撤回”承诺。平台结果不清晰由人工核实。

## 已知限制与验收关口

- 当前是源码集成，不是已验证可上线服务。实际抖音 DOM、扫码、二维码刷新、描述填写、账号核对、云机风控、AI 声明均待真实验收。
- 短信支持只覆盖识别到的输入框和按钮，且在登录/提交前等待阶段。滑块、人脸、复杂验证没有绕过或通用远程浏览器接管。
- **点击发布后出现短信/其他挑战，当前会等待结果超时并记 unknown，不会再次点击发布；不能称完整支持发布中验证码。**
- 没有作品ID/审核结果回查、定时任务、视频转码/完整媒体解码、素材删除与自动保留策略。上传只检查 MP4 容器头，不保证视频可被平台接受。
- 新账号的“预期抖音号”只是人工核对提示；会员化前必须补租户认证、强制 owner 从会话派生、资源/密钥隔离、存储配额与清理、审计、限流、服务条款及平台合规审查。现在固定 `personal-owner-v1` 只是归属扩展点，不是多租户实现。
