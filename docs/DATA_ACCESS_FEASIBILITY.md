核对日期：2026-10-27（Asia/Hong_Kong）。本次读取官方及服务商公开文档，未登录应用控制台、未取得应用权限或供应商合同、未发送账号 Cookie、未调用收费或真实账号接口。

TikHub 后续完整目录及专项接口核对见 [TikHub 数据需求审查](TIKHUB_DATA_AUDIT.md)：补充确认作品级四项深度指标及星图每日粉丝趋势候选，仍未确认完整账号日报与商业接入条件。

## 结论

官方确实提供一部分账号经营数据能力；但当前个人主体无法申请下面的“用户互动数据”能力，且该能力有商业使用场景限制。现阶段没有足够证据确认任何已调研渠道同时满足本项目全部 14 项每日指标、个人主体接入、付费多用户集成、用户仅网页登录授权这四项条件。因此不能把“已有接口文档”标记为矩阵流已获得上线使用权限。

## 官方能力与申请条件

现行[用户互动数据能力页](https://developer.open-douyin.com/capacity-center-page/capacity-detail/7180284622729658424)明确支持移动/网站应用，列出账号的视频聚合数据、粉丝及互动数据；需要申请能力并获得用户授权。准入主体限定为企业、党政、事业单位；其使用场景限制对外售卖的数据服务应用。本项目的会员运营分析场景是否可获批，须以真实场景提交申请或工单确认。注册开发者账号、取得 `user_info` 和获批本能力是不同的条件。

旧版接口文档可补充字段和口径信息，但不能单独作为当前申请资格依据：

- [用户视频情况](https://open.douyin.com/platform/resource/docs/openapi/data-open-service/user-data/get-user-video-status/)：`data.external.user`，首次授权后次日产生完整数据；每日作品变化会受删除作品影响，不能直接当成投稿次数。
- [用户粉丝数](https://open.douyin.com/platform/resource/docs/openapi/data-open-service/user-data/get-user-fans-count)：样例含 `total_fans`、`new_fans`；`new_fans` 与创作者导出的净增/吸粉口径仍需逐日对照。
- [用户点赞数](https://open.douyin.com/platform/resource/docs/openapi/data-open-service/user-data/get-user-like-number)：包含日期及 `new_like`，以日更新为主。
- [特定视频数据](https://open.douyin.com/platform/resource/docs/openapi/video-management/douyin/search-video/video-data/)：`video.data`，用户授权后查询其公开视频的播放、点赞、评论、分享等当前累计数据；不能靠一次累计查询还原过去的每日账号报表。

本项目现有 OAuth 代码只请求 `user_info`，没有获批上述数据权限。

## 与当前报表指标的对应关系

| 当前需要的指标 | 官方公开证据 | 服务商公开证据与缺口 |
| --- | --- | --- |
| 投稿量 | 有每日作品变化，受删除影响；与官方导出投稿量是否一致待验证 | 作品列表可按发布时间筛选，但并非账号每日投稿报表的直接替代 |
| 总播放、点赞、分享、评论 | 用户互动能力列出相应日增量；实际授权及导出口径未验收 | TikHub/TikOmni 文档描述作品指标；需要 Cookie，账号每日全量报表覆盖仍待验证 |
| 5秒完播率、2秒跳出率、封面点击率、平均播放时长 | 本次未找到可确认覆盖这四项账号每日报表的通用开放能力 | TikOmni 作品列表文档列出这四项作品指标；不可简单平均成账号每日指标 |
| 总粉丝量 | 官方能力及旧接口均有文档证据 | 公开账号粉丝数不能还原完整历史日报 |
| 粉丝净增、吸粉量 | 官方 `new_fans` 的精确对应关系待验收 | TikOmni 账号诊断有近7天净增；不足以确认昨天/7天/30天每日吸粉及净增覆盖 |
| 脱粉量、回访粉丝量 | 本次未找到足够的通用开放接口证据 | 本次未确认完整每日字段及历史范围 |

“未确认”表示目前没有足够证据，不代表平台绝无该能力。昨天、近7天、近30天都需要实际日期、完整每日记录、更新延迟和授权前历史范围的验收。
