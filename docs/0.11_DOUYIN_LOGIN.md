# 0.11 · 真实抖音账号授权登录

本版本只推进真实账号授权登录。原有发布、统计及 DOU+ 仍使用演示适配器。

## 当前验收状态

- 已实现官方 OAuth 跳转、一次性 state、授权码换令牌、用户公开资料查询、多账号绑定与重复授权更新。
- 已实现独立的单所有者管理会话、凭证 AES-256-GCM 加密、到期显示、退出和本地绑定删除。
- 已提供 `/douyin` 页面，首页和账号管理均有入口。
- 尚未配置真实应用凭证或 HTTPS 回调域名，**未完成真实抖音扫码验收**。配置检查通过也只表示字段格式完整，不表示平台已批准应用或权限。

## 接入前提

根据抖音官方文档，需要具备相应权限的网站应用、Client Key / Secret、`user_info` 权限及登记过的 HTTPS 回调地址。生产使用需按平台要求通过审核；若使用测试应用，需确认测试账号与权限范围。个人主体当前可申请哪些权限，仍以开放平台控制台审核结果为准，代码不能代替申请资格。

- [获取 access_token](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/account-permission/get-access-token)

## 配置与运行

1. 从 `.env.example` 复制为根目录 `.env`，填入下列配置；不要将真实密钥发到聊天、写入前端或提交 Git。

```dotenv
ALPHA_MODE=demo
MATRIX_OWNER_PASSWORD=<至少24位随机管理密码>
DOUYIN_CLIENT_KEY=<应用ClientKey>
DOUYIN_CLIENT_SECRET=<应用ClientSecret>
DOUYIN_REDIRECT_URI=https://你的域名/api/douyin/callback
DOUYIN_TOKEN_KEY=<32字节随机密钥的64位十六进制字符串>
```

可在本机终端使用 Node `crypto.randomBytes(32)` 生成随机值：管理密码使用 `base64url`，加密密钥使用 `hex`。妥善备份加密密钥；直接更换会使原凭证无法解密，需要重新授权。

2. 配置由你控制的 HTTPS 域名及反向代理，将整站代理至 `127.0.0.1:3000`，保留原始 Host。部署与域名不在本轮自动完成范围；临时穿透也必须使用平台接受且已登记的域名。
3. 在抖音开放平台登记完全一致的回调地址 `/api/douyin/callback`，不要添加自定义 query 参数。
4. 重启 `npm run dev`（正式构建使用 `npm run build` 后 `npm run preview`），从 **同一个 HTTPS 域名** 打开 `/douyin`，使用管理密码进入，查看接入检查。
5. 点击「前往抖音扫码授权」，在抖音官方页面扫码并确认。完成后回到账号列表，应出现真实昵称、头像、授权范围及到期时间。
6. 再次授权同一账号应更新原记录；授权另一个账号应新增记录。

`http://127.0.0.1:3000/douyin` 可以检查配置、查看页面，但不能作为官方 HTTPS 回调地址。不能在本地域名发起，再期望 HTTPS 域名收到相同的管理会话 Cookie。

## 接口与数据边界

| 接口 | 用途 |
| --- | --- |
| `GET /api/douyin/status` | 配置布尔检查、管理登录状态；登录后返回脱敏账号资料 |
| `POST /api/douyin/owner` | 使用服务器配置的管理密码登录 |
| `DELETE /api/douyin/owner` | 退出，撤销该会话未完成的授权 state |
| `POST /api/douyin/authorize` | 创建十分钟有效且绑定当前会话的 state，返回官方授权地址 |
| `GET /api/douyin/callback` | 消费 state，服务端换取凭证和公开资料，303 跳转至干净页面 |
| `DELETE /api/douyin/accounts/:id` | 删除本地资料和加密凭证；不代表撤销抖音端授权 |

写接口要求同源 Origin 及 `X-Matrix-Request: douyin-0.11`。真实管理会话为 HttpOnly、SameSite=Lax、12 小时有效；HTTPS 登录设置 Secure。演示会话不能访问真实账号记录。

真实账号单独存放在 `douyin_connections`，不进入旧版演示 `accounts`，不获得发布、统计或投流权限。`open_id` 是应用内用户标识，不等同于可展示的抖音号；页面不伪造抖音号、粉丝数或经营数据。

这是本地单所有者版本，不包含注册、多租户会员及团队权限管理。令牌到期后重新扫码，本轮未开发自动续期。只保留昵称、头像、应用内用户标识、授权范围、到期时间和加密凭证，不存储平台返回的全部个人资料。

开发服务已禁止输出授权回调的请求日志；如接入代理、托管日志或 APM，同样需要禁止记录回调 query 和令牌响应。回调响应使用 no-store、no-referrer，并移除地址栏里的授权码与 state。

## 验证方法

```powershell
npm run typecheck
npm test
npm run build
$env:E2E_PRODUCTION='1'
npm run test:e2e
```

授权测试使用真实 SQLite 和受控的抖音 HTTP 响应，验证正确请求格式、一次性消费、重放/并发/跨会话拦截、拒绝授权、失败不覆盖旧凭证、加密保存及登录隔离。它不能替代真实平台验收。数据库仍提供 PostgreSQL 分支，但本轮没有可用的 PostgreSQL 实例进行验证。
