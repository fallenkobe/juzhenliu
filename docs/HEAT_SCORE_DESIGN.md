# 矩阵流作品热度算法设计

日期：2026-10-28（Asia/Hong_Kong）

状态：已将核心公式和观察块接入本机 `/videos` 标题热度标记，属于未校准试验版；独立评分历史落库、作品列表/排行榜尚未实现。

当前实现标识：`matrix-heat-v1`（原设计草案为 `matrix-heat-v1-draft`）。全部权重、阈值、半衰期都是矩阵流的可调整设计参数，尚未用真实样本训练或回测；不是行业平均值、官方权重或爆款概率。

## 1. 官方算法核查

抖音《算法及模型备案公示说明》披露：个性化推荐结合用户行为，通过模型预测互动概率并排序；热榜则聚合同类事件/话题等信息计算实时热度。公开材料没有提供可直接复现的通用单视频热度公式、固定参数及完整模型。这不能推出平台内部没有算法，只说明当前无法照搬。

- [抖音算法及模型备案公示说明](https://lf3-cdn-tos.draftstatic.com/obj/ies-hotsoon-draft/douyin_agreement/70c3d13a-73cf-403a-8ecf-a16f70887c21.html)
- [抖音算法科普入口](https://trust.douyin.com/algorithm/)

TikHub 的 [fetch_item_index](https://docs.tikhub.io/485883317e0) 提供视频指数趋势，但文档未提供其计算权重；它不等于抖音个性化推荐分。本项目此前指定样本返回全0，不能当作有效热度验收。星图历史响应还可能含 `hot_score_list`，其完整定义、量纲、覆盖范围尚未核实，现有业务也未映射该字段。

接入原则：只有核实含义、日期、身份、缺失语义和单位后，才展示“供应商视频指数/星图热度”及其来源。不能把这类值与矩阵流0–100分混在一个排行榜里，也不能宣称拿到了抖音原算法。若以后取得公开且可复现的官方单视频算法，再作为独立版本评估替换。

## 2. 产品目标与分数口径

衡量“截至最近查询，这条作品最近是否在起量”，而不是终身表现、内容好坏或会不会获得平台推荐。

- 每个作品提供热度字段/状态：可计算时展示0–100分及更新时间；数据不足时展示“待积累/缺少播放数据”，不能硬填0。
- 主榜以近期增长为主，老视频再次爆发也可以高分。
- 历史累计量有帮助，但仅占最多10分，并随发布年龄衰减。
- 发布年龄不乘整个分数，避免老视频永久无法翻红。
- 单次查询只有累计值，无法知道最近起量速度，不能用“累计播放÷发布以来小时数”冒充近期速度。
- 点赞/评论/分享是事件计数，播放是次数；其比值不是独立观众的转化概率。当前也无法分离自然流量与投流；热度标签要标明含投流可能性。
- 页面已有快照和净增量继续保留；热度不替代真实计数。

## 3. 输入与观测区间

必需：作品ID、类型、数据来源、发布时间、快照查询时间、累计播放V、点赞L、评论C、分享S。收藏仍展示，可在后续单独校准后加入v2，v1不为了堆指标重复加权。

从同作品、同来源的有效相邻快照开始，构造截至最新查询的最近观察块：

1. 从最新相邻区间向前合并连续区间，直到跨度至少1小时。不能在区间中间切割或按小时虚构数据。
2. 不足1小时但已达到30分钟时可给“短窗口参考分”；不足30分钟时暂不提供正式热度，继续展示累计/增量。
3. 合并块内每项计数须完整；不得跳过缺失值、来源变化、时间异常或播放回撤。遇到断点停止，等待新的完整观察块。
4. 单个查询间隔超过6小时但不超过48小时，可提供“长区间平均热度/低置信”参考，不标为实时热度，不参加实时榜；超过48小时只保留区间增量，暂不给当前热度。
5. 正常观察块跨度1–6小时。大量相同频率查询拆分同一观察块不会凭空制造更多增长；每个块使用起止累计差除以实际时长，不能简单平均每次查询的速度。
6. 在最近观察块之前，按同样方法构造一个不重叠的前观察块，供加速/降速比较。不足两块时动量调整不启用，而非声称增长趋势为0。
7. 不依赖前端“最近100条”数组：后端按时间读取足够的原始快照及前驱，最多48小时候选范围；高频样本截断时必须降低状态而非计算假趋势。

`Δt` 的单位为小时，所有累计差先以BigInt算出；UI仍显示带正负号的原值。

## 4. 核心公式

### 4.1 有界标准化

对非负统计量使用：

```text
N(x, T) = clamp( ln(1+x) / ln(1+T), 0, 1 )
```

对数压缩避免百万级历史播放完全压过新视频；T为“达到该分项满分的设计锚点”，并非行业基准。输入原计数不截断，只在评分变换时封顶。

### 4.2 增长速度 A（基础贡献最多60分）

每项每小时净增长速度：

```text
vV = max(0, ΔV) / Δt
vL = max(0, ΔL) / Δt
vC = max(0, ΔC) / Δt
vS = max(0, ΔS) / Δt
A = 0.55 N(vV,10000) + 0.20 N(vL,500)
  + 0.10 N(vC,100)   + 0.15 N(vS,50)
```

点赞/评论/分享负差保留在真实增量中；用于正向活跃度贡献时取0，不把减少当作正向互动。播放回撤属于当前口径无法解释的情况，不输出有效热度，标“计数回撤/待核对”。修正后的数据可在后续两个干净快照间重新建基线，不把旧异常跨过去。

### 4.3 互动效率 Q（最多再贡献25分，须有活跃度）

实际页面同时展示累计比 `L/V、C/V、S/V`；评分优先用最近观察块的保守比值：

```text
rL = max(0,ΔL) / (ΔV + 200)
rC = max(0,ΔC) / (ΔV + 200)
rS = max(0,ΔS) / (ΔV + 200)
Q  = 0.45 N(rL,0.05) + 0.20 N(rC,0.01) + 0.35 N(rS,0.005)
```

200是收缩强度，防止10播放5个赞因50%原始比值冲顶。5%、1%、0.5%是初始评分锚点，不是从资料查到的官方标准；增加真实样本后回测调整。

这里的比值是“区间净互动/新增播放”的代理指标：互动可能发生在之前的播放之后、计数更新时间也可能不齐，因此不能称为真实新观众点赞转化率。

- ΔV=0且全部互动净增量≤0：A=0，Q作为不贡献项，不报告观众转化率。
- ΔV=0但有正互动：可能是延迟互动/源数据不同步，保留增量，热度标为部分数据，不把分母强设1来制造高比率。
- 比值超过100%不删除原值（评论/分享可重复），记录提示；评分仅通过N封顶，不能据此自动判定刷量。
- 评论数少于点赞权重、分享效率权重较高，属于矩阵流的运营偏好，不能声称“抖音认为分享比点赞重要”。

### 4.4 动量 G（最多加/减5A分）

比较最近观察块和前观察块的加权每小时速度：

```text
Z = vV + 5vL + 10vC + 15vS
G = clamp( log2((Z_recent + 200)/(Z_previous + 200)) / 2, -1, 1 )
    × min(1, ΔV_recent/200, ΔV_previous/200)
```

200/h是稳定项，避免从1变2就因翻倍产生巨大加成；样本门控进一步抑制小样本。四倍提速接近+1，显著降速接近-1。

启用条件：两块都有效、均≤6小时、时长比例在0.5–2之间、来源一致。否则G不启用，公式不加动量分，UI显示“动量待积累/窗口不可比”。前块播放为0时门控使动量加成不启用；老视频复燃仍由当前速度A和效率Q获得高分，无需靠倍率制造爆发。

### 4.5 累计基础 B 与发布时间 F（合计最多10分）

```text
B = 0.55 N(V,100000) + 0.20 N(L,5000)
  + 0.10 N(C,1000)   + 0.15 N(S,500)
F = 2 ^ (-作品年龄小时 / 72)
```

作品年龄截至当前快照查询时间，发布时间缺失/晚于查询时间则该部分未知，不假装刚发布。72小时为初始半衰期：3天后基础贡献减半，6天后为四分之一。

### 4.6 最终热度

```text
H = round(100 × clamp[A × (0.60 + 0.25Q + 0.05G) + 0.10BF, 0, 1], 1)
```

分项上限：近期速度60、互动效率25、动量±5、带时间权重的累计基础10。Q和G均以A门控：没有近期增长，不会仅凭历史高互动率继续保持高热度。

举例：老视频A=1、Q=1、G=1时，即使F趋近0，仍可接近90分。老视频累计再高但确认近期停止增长，A=0，只剩衰减后的少量基础分。

## 5. 数据完整性和时效

正式分要求V/L/C/S完整、发布时间有效、观察块有效；任一指标缺失都不得当成0，更不能按剩余项重新分配权重把缺数作品抬高。可在UI显示已知分项，但完整热度为null，标“数据不足”，不与正式分混排。当前图文缺少可靠播放的业务路径因此需要先接入累计播放才可取得完整热度。

置信标签与分值分开，不能简单用“热度×置信度”让缺数变成低热度：

- 标准窗口1–6h、四项完整、ΔV≥200：基础信息较充分。动量有无单独标记。
- ΔV<200、观察块30–60min：参考/低样本。
- 观察块6–48h：长区间平均，低时间分辨率；无法判断增长发生在哪几个小时。
- 首条快照、缺少播放、来源改变等：待积累/数据不足/待核对。
- 当前时间距离最新查询超过 `min(24h, max(2h, 2×观察块小时数))`：标“已过期”，移出当前热榜；保留查询时评分，不擅自当作停止增长，也不轮询供应商。

所有评分标“截至某次查询”。未查询期间不能用墙钟自动给H降分来伪装真实降温；只有新观测确认增长减缓时，更新热度。

## 6. 展示与排序

作品列表每项显示“矩阵流热度 76.4 / 100”、数据截至时间、状态；没有数据显示“待查询/待积累”，不因进入列表自动发起付费查询。点击已有“查看分析/更新数据”才按现有规则获取快照。

分析页显示A/Q/G/BF贡献解释、观察起止时间与净增速度，帮助用户知道是量大、效率好还是突然加速。热度历史来自当时有效快照，不拼成官方历史。

热度较上一次可比分数上升红、下降绿、持平灰。算法/参数版本不同，来源或正式/参考状态不同，不直接输出涨跌箭头。颜色继续遵循用户确定的红涨绿跌。

正式/参考/过期/不可计算分别展示，默认榜单仅排序同来源、同内容类型、同算法版本且足够新鲜的正式分；明确观察窗口可不同，排序仍是有限观测下的估计。视频和图文不要在未校准前混排。禁止把平台指数与矩阵流分混排。

## 7. 合成场景检查

可复现脚本：`node scripts/simulate-heat-score.mjs`。脚本只验证核心公式、非真实数据；不访问网络/数据库，不代表窗口拼接或生产代码已实现。结果写到Git忽略的 `.data/heat-score-simulation.json`。

| 合成场景 | 草案分数 | 预期 |
| --- | ---: | --- |
| 新视频3小时，最近1h新增播放4000、赞240、评40、分享32，较前1h提速 | 84.6 | 较高热度 |
| 发布180天，同样当前增长 | 77.2 | 年龄不压死当前表现 |
| 发布180天，最近1h新增播放20000、赞1000、评200、分享100 | 89.8 | 可识别后期爆发 |
| 历史播放200万、最近确认没有新增、已发布180天 | 0.0 | 旧总量不冒充当前热度 |
| 最近1h仅10次播放、5个赞 | 14.7 | 高比率小样本不会冲顶；正式状态应低样本 |
| 同一新视频从前1h播放4000降至最近1h的200 | 38.3 | 可识别降速 |
| 缺少播放，或累计播放出现负差 | 不出完整分 | 不把异常/缺失作为低热度 |
| 24h才查询一次 | 参考分55.9 | 只解释为长区间平均 |

相同速度、累计值和年龄，1h与2h样本分别60.7/62.0：速度分相同，但2h曝光样本更多，效率收缩较少。这是样本支持变化，不是简单“查询次数越多分越高”。

该脚本没有完成生产窗口合并、异步更新时间识别、来源校验及UI联调。它不能证明算法能预测真实爆款。

## 8. 校准与实施顺序

1. 实现纯函数与输入有效性检查，不增加外部接口；先覆盖首条、零/负、缺失、时间回退、跨来源、乱序、超大整数、短间隔合并和窗口边界。
2. 后端从原始快照派生热度并持久化版本化评分记录（作品ID、快照时间、起止区间、参数版本、分项、状态、异常标记），与原始快照分离；不覆盖历史评分版本。
3. `/videos` 显示解释，作品列表按需读取已保存热度；不批量查询未分析作品。现有仅携带fetchedAt的快照结构需要由可信报告补充并核对发布时间和内容类型。
4. 针对同来源同类型作品，按时间切分历史样本，用后续6h/24h的净播放增量做结果指标。观察排名相关性、Top-K后续起量比例、短时抖动、小样本误报、老视频复燃漏报和数据陈旧率。
5. 先积累至少200条有效作品及1000个有效观察区间作为调参起点（不是统计显著性保证）。参数冻结在明确版本；不能按当前页面的几个作品实时改锚点。
6. 达人/账号规模会影响绝对热度；如未来需要衡量“超过该账号平常水平”，另做账号相对表现分，不能悄悄混入全局热度。若要区分商业投流，需真实可分离字段。
7. 噪声仍明显时可评估按实际时间加权的指数平滑，验证更稳定是否牺牲复燃响应；本草案先不叠加更多参数。[NIST指数平滑说明](https://www.itl.nist.gov/div898/handbook/pmc/section4/pmc431.htm)支持“近期观测权重更大”的通用方法，但不提供抖音权重，也未验证本文公式。

本次未新增真实TikHub请求，没有承诺刷量识别、平台推荐预测或收益预测。


## 9. 当前实施边界

分析页按报告查询时间只读计算热度，不增加供应商调用；从数据库读取过去48h原始快照及一个前驱，不受前端100条限制，超6000条候选拒绝截断计算。返回试验版本及计算分项，标题右侧火焰可展开说明；分数0是实际计算结果，缺失/首次仍为null。浏览器每分钟仅本地检查是否过期。

本轮没有建立独立版本化评分表，不对外提供热度历史，不自动请求作品列表中尚未分析的视频。现有累计比率另行展示的设计尚未实施，标题说明当前只展示贡献分和观察区间。真实样本回测、分群校准及排行榜仍待后续。新增纯函数/服务/浏览器检查已完成；这些证明实现符合规则，不证明能预测抖音推荐。
